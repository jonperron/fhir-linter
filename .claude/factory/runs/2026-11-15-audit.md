# Factory run — audit 2026-11-15

One orchestrator session took items 1–9 of the 2026-11-15 audit, then
items 10–13 found by a gap analysis of the official suites, and ran one
`issue-driver` per item, each in its own worktree, with one PR per item.
Responders, rebases (`gh pr update-branch`) and `behaviour-differ` runs
followed where needed. This file records the outcome and what the run
taught us about the factory. The agent and profile changes in the same
PR come from the lessons below.

## Lessons and the changes they led to

| What happened | Change |
|---|---|
| Responders (Sonnet) skipped the build, linter, test and openspec agents and hand-edited specs (#112 follow-up, #113, #114 twice); the orchestrator ran them instead | `bot-review-responder`: one pass runs the full agent set and the spec-sync subagent; never hand-edit specs. `project.md`: a routing note adds `build`, `linter`, `test` for every task |
| `rtk` showed "caveman: body elided" in Read, `cat` and `sed`, even through `rtk proxy`; a security reviewer saw no bodies (#1, #5, #6, #7, #10) | `project.md`, Shell quirks: the workarounds that worked |
| `gh pr checks --watch` under `rtk` printed a summary and exited early (#1) | `project.md`, Shell quirks: poll with your own script |
| Grep and Glob tools were missing for drivers, though the profile said to use them (#5, #8) | `project.md`, Shell quirks: `/usr/bin/grep` and `find` |
| `tox` not on `PATH`; the profile's vitest command failed 14/20 from the worktree root (#6) | `project.md`, Quality gate: `uvx tox`; vitest with `--root` and an absolute definitions path |
| Agents overwrote each other's `wait.sh`, `pr.md` and a harness `Cargo.toml` in the shared scratchpad (#6, #12) | `project.md`, Shell quirks: one scratchpad subfolder per agent |
| Sourcery's weekly budget (2.5M diff characters) ran out after about 6 PRs; it posted only a notice. The user chose to wait for the reset | `project.md`, Automated PR reviewer: the budget and the `@sourcery-ai review` re-request |
| Drivers ended at 171k (S-size, #8; 167k at the bot wait) and 178k (#9, despite "report at 110k"); #7 reached 148k. #13, given a 70k budget, ended at about 74k | `loop.md`: context budget checkpoint at about 100k with the PR open; `issue-driver`: the budget input and the exception to the bot wait |
| Agents skipped the worktree setup and tests failed; a PR branch was checked out in a finished agent's worktree | `project.md`, Worktree setup: run it first; the new-local-branch route |
| A `git fetch` hit a ref-lock race with another agent fetching (#10) | `project.md`, Git quirks: run it again |

Not changed. These are orchestrator practice and do not belong in an
agent file:

- Split M-size items before handing them to a driver, or give a lower
  context budget.
- Finished agent worktrees are not cleaned up; remove them once their PR
  is merged.
- When Sourcery's budget runs out, decide whether to wait (this run:
  wait) and re-request the reviews after the reset.
- The guard also rejected several `sed -i` in one call and an `ls` on an
  `eval/` path; both are covered by the existing Shell quirks.
- A broad `sed` clobbered a test helper (#8 follow-up); it was repaired.
  Prefer the Edit tool for edits.
