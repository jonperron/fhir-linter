# Factory run — audit 2026-11-08

One orchestrator session took the 16 backlog items (F1–F16) of the
2026-11-08 audit and ran one `issue-driver` per item, each in its own
worktree, with one PR per item. A `bot-review-responder` ran after each
PR for the Sourcery review. This file records the outcome and what the
run taught us about the factory. The agent and profile changes in the
same PR come from the lessons below.

## Lessons and the changes they led to

| What happened | Change |
|---|---|
| 5 of 6 drivers in `pr` mode reported before the Sourcery review | `issue-driver`: the bot wait is mandatory unless the caller runs it |
| Drivers skipped `rust-reviewer` on "trivial" Rust diffs, and the openspec agent | `loop.md`: reviewers are mandatory for routed files; spec sync goes through its subagent; the report lists each reviewer's verdict |
| A driver declined two reviewer MAJORs by argument alone; tests later showed they were harmless, but only because someone asked | `loop.md`: decline a CRITICAL or MAJOR only with a test or code evidence, cited in the PR body |
| A pass rate dropped (F1 XML, F3 JSON) and needed a manual trace | `loop.md`: explain every flipped case before accepting a lower rate |
| F3 + F15 together fell below F15's floor (stacked PRs, one shared harness) | `loop.md`: measure on top of sibling PRs that set floors |
| Two responders fixed the same Sourcery comment on parent and child PRs | `bot-review-responder`: read the parent PR's bot threads first |
| Sourcery sometimes posts only a reviewer's guide and no review | `bot-review-responder`: read issue comments; guide-only means nothing to answer |
| The worktree guard refused chains, loops, heredocs, `$(...)`, `--jq`, `\|`, `git -C` to the primary checkout and `eval/` paths; `rtk` hid `cat`, `grep` and `cargo test` output; no Monitor tool, no foreground `sleep`, no `/usr/bin/gh` | `project.md`: new "Shell quirks" section |
| The setup loop was refused; agents improvised a wider symlink that overwrote the tracked `definitions/r5/README.md` (2 reports) | `project.md`: setup as separate commands, with a warning about `README.md` |
| Agents inherited Opus; 7 in parallel hit the 5-hour usage limit | `bot-review-responder` and `pr-rebaser` pinned to `model: sonnet`. The Sonnet-run responders and rebaser did their jobs; `issue-driver` stays on the default, because three Sonnet drivers skipped reviewers |

Not changed. These are orchestrator practice and do not belong in an
agent file:

- New agent files only show up after Claude Code restarts. The first wave
  ran as `general-purpose` agents told to follow `issue-driver.md`.
- Keep about 4 drivers in parallel.
- Start a child PR's bot responder after the parent's has finished.
