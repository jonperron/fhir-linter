# Factory run — final audit 2026-11-25 to 2026-11-26

A full audit of `main` at 3e7a606 (four parallel read-only reviewers,
one per area) found 20 issues. Two more read-only passes then covered
the code the first one had skipped, adding 9 issues (21–29). One
orchestrator session ran one `issue-driver` per PR in four lanes:
validator, definitions + bindings, FHIRPath, parser + CLI. PRs that
share a spec file ran one at a time. This file records the outcome, the
follow-ups and what the run taught us about the factory.

## Follow-ups

- FHIRPath step budget does not charge work inside a single builtin
  (long-string scans per item; quadratic comparisons of temporals and
  objects in `distinct`, `union`, `~`, `repeat`). Marked `shortcut:`.
- PROFILE_011 on Quantity with different units (UCUM conversion).
- XML input with a removed choice variant may get STRUCTURE_001 twice.
- XML spans may point one byte before the element (column 47 for an
  `<x>` at byte column 48), seen during #212.
- #213's linear-time test is now a 1k-element smoke check: it no longer
  catches a quadratic regression, only wrong results.
- 20b, 25, 29 above.
- Smaller audit items left out: `indexOf` via std, `distinct()` hashing
  of objects, the `Registry::shared` global lock, the `Span` doc versus
  XML BOM offsets, `terminal_safe` on JSON / SARIF output.
- `contentReferenceProfile` value type (`uri` or `canonical`) is not
  decided: its definition is not bundled, so `valueCanonical` is ignored.
- `file_uri` Windows branches are untested on Linux.

## Lessons

| What happened | Change |
|---|---|
| Two audit findings were wrong once a driver reproduced them (FHIRPath `\u+`, `highBoundary`), one overstated (symlink loop) | None needed: "reproduce first, else stop and report" in `issue-driver` worked. Keep audit findings marked VERIFIED / SUSPECTED |
| A bot-review responder skipped the worktree setup; tests failed on the missing `tests/fixtures` submodule and looked like a flake (#207) | Brief every responder to run the setup first, as for drivers |
| Validator drivers ended at 105–146k tokens; V6 and F2 stopped at the budget with the PR open and needed a finisher | Expected for M-size validator items: plan a finisher (`bot-review-responder`) instead of raising the budget |
| Four drivers paused on the 5-hour usage limit twice; `SendMessage` resumed each from its transcript | Already in memory (~4 agents at once, resume with SendMessage) |
| Sourcery's weekly budget ran out after about 9 PRs; the user chose to merge on our own reviewers plus CI | Ask once per run; record the choice here |
| PRs merged after other PRs landed were re-run on CI with current `main` (`gh pr update-branch`) before merging | Keep: two PRs touched the validator from different sides (#206 after #207) |
| A wall-clock regression test (60 s bound) came back from a driver told to avoid timing (#213) | State "no wall-clock assertions" in the brief and accept a smoke check when no count hook exists |
