# Code Organization

- Many small files over few large files
- High cohesion, low coupling
- 200-400 lines typical, 800 max per file
- Organize by feature/domain, not by type
- No circular import

# Code Style

- No emojis in code, comments, or documentation
- Immutability always — never mutate objects or arrays; prefer `readonly` and `const`
- Use 2 spaces for indentation (never tabs)
- Use meaningful, descriptive variable and function names
- Avoid abbreviations
- Use camelCase for functions/variables, PascalCase for types/interfaces/classes, UPPER_CASE for constants
- Strict mode is on; avoid `any` and unsafe type assertions
- Explicit return types on exported functions
- Named exports only; no default exports
- Pure ESM; local imports use the `.js` extension
- Do not edit the `.d.ts` and glue files generated by `wasm-bindgen`; change the Rust side instead

# WASM Boundary

- Rust errors reach TypeScript as thrown `Error`s, never as panics
- Diagnostics returned by `validate` / `lint` keep the shape of the Rust `Diagnostic`; do not introduce alternatives
- Await the WASM module initialisation before calling any exported function
